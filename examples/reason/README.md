# C4 authored usage assets — not executed

These examples describe the local SDK/CLI structure only. They are not qualification evidence. Follow [the C4 guide](../../docs/implementation/C4_REASONING_RUNTIME.md) for limits and authority.

1. Choose one workspace and separate C1/C2/C3/C4 paths. Set `model_revision` in `inquiry.json` to an existing C3 revision. Add explicitly selected `world_ids` and C1 evidence ranges. A range cannot exceed the source bytes; binary data remains metadata-only in this increment. The empty example intentionally makes no substantive world claim.
2. `edi --workspace demo reason-investigate examples/reason/inquiry.json` stores the cut. `reason-get demo-inquiry` returns the current episode. `reason-step examples/reason/student-step.json` durably reserves an export job; it performs no model call.
3. Read the returned job ID, then `reason-export-job demo-inquiry JOB_ID` returns control/protocol, data and the response schema. Unbound jobs accept only explicitly human-authored proposals. Actual imported model output requires an exact pinned binding configured before the inquiry. The caller must not dispatch until a real gateway admits tokens/context/cost. No such gateway is installed here.
4. Author a `Response` JSON against `schemas/reason-response.schema.json`, copying the real inquiry/job/context identities and binding. State attribution, concise rationale, limitation and unknowns. Up to three hypotheses can carry candidate-only typed changes. Cite only exact evidence references in the returned cut. Import with `reason-import-response RESPONSE_JSON`. Never substitute fabricated observations for missing data.
5. C0 reads the episode's linked outbox artifacts and may acknowledge receipts with `reason-outbox-ack ACK_JSON`. Tests/access proposals are not executed or granted by this acknowledgement. `reason-rank-frontier demo-inquiry` returns a declared heuristic ranking and retained omissions, not information gain.
6. If a response contains candidate changes, author a `reason-submission` request with workspace/inquiry/request/response IDs and reason, then use `reason-build-patch REQUEST_JSON` or `reason-submit REQUEST_JSON`. C3 controls candidate admission and stale-base rejection. Reuse exact request identity to reconcile an interrupted submission; do not silently rebase.
7. Use `reason-step examples/reason/yield-step.json` when no job is pending. For a pending job, explicitly request `cancel-pending`; the episode yields with usage unknown and the reservation is not refunded. Further rounds require a new inquiry after the bounded controller yields.

The CLI is a trusted local operator surface. No native inference, automatic adjacent discovery, provider call, training, numerical analysis or external notification is demonstrated by these files.
