## Concrete grammar and model-to-code correspondence

The current IR is `edi.stock-flow-ir/1.0`, stored explicitly in a pinned native C3 `response-relationship` under `structure.mechanism.edi_ir_v1`. It is a flat expression DAG, not Python, symbolic source to evaluate, arbitrary functions or an LLM-generated script. No `eval`, `exec`, dynamic code compilation or arbitrary import is used to interpret a model.

| Grammar item | Required semantics |
| --- | --- |
| Stocks | Unique symbols, explicit C3 stock versions, coherent units and optional lower/upper bounds. Scenario supplies every initial stock value; no hidden default or reset. |
| Parameters | Unique symbols, values, units and finite lower/upper domains. Scenario changes stay within the declared domains. |
| Boundary drivers | Typed parameter-like inputs with defaults; optional strictly ordered piecewise-constant schedules beginning at scenario start. |
| Nodes | Unique IDs; `constant`, `read`, binary `add/subtract/multiply/divide/min/max`, unary `negate`, or unary piecewise-linear `lookup`. Every operator has exact arity and rejects ignored fields. |
| Constants/reads | Constants carry finite value/unit; reads name declared stock/parameter/driver/time symbols. `time` is reserved and measured in seconds. |
| Lookup | At least two strictly increasing finite x coordinates, x/y units and explicit error/clamp extrapolation. No hidden extrapolation, duplicate-x jump or arbitrary interpolator. |
| Flow | Unique C3 flow version and rate node; one source, one sink or one of each. Source/sink differ. Internal identity transfers use one rate and one cumulative transfer, with opposite stock incidence. |
| Provenance | Source statement, formalization rationale/status and explicit assumptions. Source transcription and proposed correction are separate authored versions; no silent repair of Meadows equations. |
| Unknown/advanced mechanisms | A qualitative/unsupported law never acquires a fabricated rate. Explicit required capabilities outside the subset return unsupported. Algebraic cycles/DAEs, delays, discrete/hybrid events, actor policies and topology transitions are not approximated silently. |

Compilation topologically orders node dependencies; stock feedback through derivatives is allowed and distinct from an algebraic cycle. Numeric execution computes `d(stock)/dt = sum(inflows) - sum(outflows)` with each flow evaluated once per RHS call. Negative rates fail with a diagnostic; reverse transfer requires its own declared flow. Units are checked over all model expressions, including unused declared nodes; the compiler does not infer causal truth from the DAG.

Native C3 correspondence is deliberately strict. The response's participant set must exactly match IR stocks/flows. Each native stock's inflow/outflow inventory must match the IR incidence. Each native flow uses the exact `source/out` and `sink/in` participant convention; an explicitly named response must be the pinned governing response. Stock quantities must be cardinal and have the same unit label. Supplied native rate metadata must use the exact coherent stock-unit `/s` declaration. Native bound descriptors must map to the IR bounds. Native response parameter descriptors, if present, must match the IR scalar parameter defaults. Unmapped native domains/capacities/delays, stock reserve/access rules, flow prerequisites, pending commitments, resource allocation or transformations return unsupported rather than disappearing.

These are narrow **engineering conventions**, not an assertion that every native model already has this shape. A different justified formalization needs its own explicitly versioned mapping/backend. The compiler accepts only `accepted_for_use` native records by default. `candidate-exploration` explicitly permits candidate records and labels the analysis hypothetical; rejected/withdrawn/retired records cannot enter this cut. A compiled `supported` status means grammar/mapping support, not empirical acceptance, solver availability or a certified forecast.

## Units, scales, constraints and mathematical assumptions

Units carry a symbol and dimension-power map. Supported coherent SI symbols/compositions are built from the registered bases and selected derived units with multiplication/division/integer powers. Arbitrary affine or prefix conversion is not supported. Unknown units require a `declared-domain` basis and an explicit `domain:` dimension; for example tree counts, currency and insects need not collapse into an interchangeable scalar. Known SI labels cannot contradict their fixed dimensions. Matching unit dimensions is an authored modeling claim about measurement meaning, not proof of real-world correspondence.

Add/subtract/min/max require equal dimensions; multiplication/division combine dimensions; lookup input/output dimensions are explicit; each rate must have its stock's quantity/time dimensions. Internal identity transfers require compatible source/sink dimensions. Numerical values are floating-point, not exact arithmetic. No automatic normalization, unit conversion, conservation fix, state clipping, flow rescaling or lost-backlog initialization occurs.

The supported state is an ordinary finite stock vector with `stock-state-only` history semantics. This assumes all required Markov state is represented. The system cannot establish that assumption from equations alone. Fixed/history-dependent delays, queue identity, event ties, resources with contention, state resets, state-dependent policy changes, arbitrary stochastic distributions and nonlinear aggregation/refinement require future capabilities. They remain representable in C3 but unsupported numerically here. General causal/system identification, Bayesian posterior inference, automatic system traps/leverage diagnosis and verified biological/ecosystem understanding are not implemented by the scenario runner.

Conservation diagnostics integrate each flow alongside the stock vector, then compare stock change with signed cumulative transfers. This is an accounting-consistency diagnostic using the **same equations and solver**, not an independent numerical-error estimate or empirical conservation test. Shared-resource arbitration/conversions/loss accounting are not automatically inferred. Domain authors can express simple joint rate limits through supported arithmetic/min/max, but unmapped native allocation semantics still reject compilation.

## Numerical backend and clock policy

The selected initial preference remains **SciPy**. The optional `numerical` extra pins the already present local metadata versions **SciPy 1.17.0 / NumPy 2.5.3**; nothing was installed in this increment. The run request pins those versions. Missing/mismatched packages return explicit unavailability, retained as an unsupported run; there is no silent homegrown solver fallback. Numerical packages load only when a numerical scenario actually executes.

The adapter uses `solve_ivp` with an explicit method (`RK45`, `DOP853`, `Radau` or `BDF`), relative/absolute tolerances, positive maximum step, output grid and initial state. See the pinned [official SciPy 1.17.0 API](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.integrate.solve_ivp.html), checked 20 October 2026. The API supplies ODE integration, local error control and root-event reporting; it does not establish model adequacy or general delay/DAE/hybrid semantics. Native `solve_ivp` stiffness-related method choices and event limitations are why those policies are explicit rather than guessed.

Driver changes split integration into continuous segments on one relative clock. The driver value at segment start applies on that half-open segment; the old segment advances to its endpoint before the next value is applied. No stock reset occurs. Trajectory times include the requested grid plus segment boundaries and any reported terminal-bound event. `time_origin` states whether that relative clock has an absolute anchor; unknown clock correspondence stays unknown for C6.

Bound events stop at the declared stock limit plus a configured numerical margin; reported samples also receive bound checks. A violating sample is retained for diagnosis and the trajectory becomes partial. Bounds are never repaired by clipping. SciPy's sign-change event detection can miss multiple crossings within a step; sampled checks and a maximum step do **not** certify continuous-time feasibility. A lookup may fail at an intermediate solver stage outside its declared domain before an event is resolved; that is an explicit partial/failed integration, not permission to extend the law. Scalar absolute/bound tolerances apply in each state's declared coherent numeric units; heterogeneous-scale/per-variable tolerance policies remain future work. Numerical refinement, discontinuity fixtures and error adequacy are unrun obligations.

## Sensitivity, uncertainty, output mapping and forecast status

Baseline plus at most eight named parameter variants share one total work budget. Each initial state is explicit; parameter and driver bounds are checked; variants do not change topology or secretly refit the model. Completed variants supply pointwise minimum/maximum values labeled **finite-scenario ranges**, not posterior/credible/confidence intervals. Unvisited structures, missing drivers and other parameter regions remain unquantified. Partial variants are excluded from the range and retained separately. One-at-a-time variants supply final-state finite secants with output-unit/parameter-unit meaning; multi-parameter variants do not masquerade as a derivative. Nonfinite sensitivity calculations are omitted with a diagnostic.

Every trajectory retains its variant, time grid, state symbols/values, cumulative flow integrals, final time, parameter values, balance residuals, work count and diagnostics. Units/identities come from the embedded immutable compiled model. `ScenarioSpec.correspondence` declares the modeled stock, observation channel, instantaneous aggregation and limitation. C1 evidence refs are checked against occurrence/workspace/hash/range/origin/lineage metadata; **scenario numbers remain caller-declared conditions**, not automatically parsed or verified observations. Original source receipt/commit/event/report times and identities stay visible. Generated/simulation origins cannot become independent corroboration merely by being cited.

Run output has `origin_class=simulation` and `forecast_seal=unsealed; C6 prospective registration required`. Immutability here does not establish a prospective independent comparison. C6 must later seal eligibility, expected/outcome correspondence, availability cuts and scoring rules; actual outcomes remain independent C1 evidence. C0, not C5, would ingest generated payloads into C1 under the correct lineage. The qualitative mode returns structural/assumption/unsupported diagnostics, not an automatically invented causal explanation or precise trajectory.

## Persistence, cancellation and recovery

C5 has its own lazy `.analyze.sqlite3` sibling database. C0 validates all five owner paths/workspaces. C1 recording neither opens C5/C3 nor loads numerical packages. Compilation persists an immutable supported/unsupported artifact with model/dependency cut, diagnostics and hashes. A repeated compile request returns the original artifact before rereading context. A repeated completed run returns its original result before rereading evidence or executing anything. Changed request/semantic profile/compiler/implementation identity conflicts; operational quotas may be raised explicitly without changing a request's model/solver/scenario.

A run intent and workspace worker reservation commit **before** execution. An existing unfinished intent returns unknown completion rather than repeating numerical work automatically. The final run result commits once and releases the reservation. A process crash leaves a durable unresolved intent. C0 can query status, request cancellation, or explicitly interrupt/fence the expected worker attempt. Fencing prevents stale-result admission; it does not kill or prove termination of an external process. The caller must arrange actual process supervision before treating this as production recovery.

Cancellation is a durable flag, checked at segment boundaries and periodically (every 32 RHS calls) during integration. A cancellation racing result commit cannot be recorded as successful completion. An interrupt request fences the old attempt and records an immutable interrupted outcome with unknown prior worker usage. Control IDs are idempotent and retain their rationale. Each run pre-reserves its maximum result size and sixteen control receipts (up to 16 KiB each); cancellation/finalization do not need another logical artifact-quota reservation. A physically full/unavailable disk can still prevent a commit and must be repaired. Interrupted work is not silently zero-cost or rerun under the same ID; a deliberately new scenario request preserves that history.

Local accounting is conservative JSON reservation, not a physical SQLite/WAL/filesystem limit. Restores, retention/export, migrations, backups across all owners, process isolation and HA/failover remain open. An immutable result/hash says what was recorded, not that its model or output is true.

## Operating envelope, failures and critical retrospective

Defaults: 256 KiB request, 1 MiB compile context, 4 MiB retained result, 128 selected world records, depth-four dependency query, 100,000 admitted output cells, 50,000 RHS calls shared across baseline/variants, cooperative 30-second operation budget, five-second writer timeout, 10,000 logical retained artifacts and 1 GiB reserved artifact bytes, plus a 256 MiB disk reserve. Grammar caps are 32 stocks, 64 flows, 64 parameters, 32 drivers, 256 nodes, 128 lookup points and at most nine scenario variants. Output/storage estimates are checked before work; excessive grids/variants reject explicitly. These are finite local proposals, not measured speed/capacity or arbitrary-scale/HA guarantees.

Usage records RHS calls including failed work, elapsed C5 compute, requested/retained variants and zero model calls/tokens. They do not claim measured energy/CPU utilization or complete capture/context/persistence/C0/C6 path cost. Callback timeouts are cooperative; native solver linear algebra/import/OS calls are not forcibly preempted. Fair scheduling and hard deadlines require future supervised workers.

| Failure / condition | Detection and consequence | Containment / return path |
| --- | --- | --- |
| Missing/changed/inactive reference or incomplete dependency cut | Compilation cannot certify the selected executable context. | Persist unsupported diagnostics; C0 requests a new/expanded formalization, never an implicit current-head rebase. |
| Wrong unit, algebraic cycle, unknown operator or hidden native flow/resource/backlog | Compile support rejected. | Preserve source statement/model; use a separately declared future backend/mapping. |
| Negative/nonfinite rate, lookup-domain failure, solver failure or stock-bound stop | No completed full-horizon result claimed. | Retain successful segments/partial diagnostics; do not clip or fabricate values. |
| Work/output/disk limit | Admission rejects, run yields partial, or commit status becomes unknown. | Preserve earlier artifacts, query original intent/result, adjust operational capacity explicitly; no automatic rerun. |
| Crash, duplicate request, cancelled/fenced worker | Intent/result/attempt/control ledger distinguishes cases. | Query, cancel or fence exact attempt; final result immutable; old worker cannot overwrite. |
| Generated echo or scenario range presented as knowledge | Artifact origin, assumptions, ranges and unsealed forecast status expose the distinction. | C6 independent evidence/registration remains required; no self-admission. |

KISS: one restricted flat IR, one dimensional compiler, one optional established ODE adapter and one local store; no general language, agent framework, duplicate world graph or service per system concept. A custom numerical solver was considered and deferred because its new numerical correctness burden is unnecessary before evidence of an advantage. PySD/SimPy/Mesa/DAE/delay adapters remain conditional choices, not dependencies activated by this increment.

Five Whys: predictions require mechanisms; mechanisms require a formal law and conditions; formal laws require unit/reference/domain/constraint checks; those checks need pinned source/model structure and explicit unsupported outcomes; therefore C5 compiles a narrow declared IR and preserves its provenance instead of executing an unconstrained LLM answer. This is design rationale, not proof of correct causal inference.

Waterfall/return path: mission → IMP requirements → F50–F53 → grammar/interfaces/operating envelope → implementation → specified future numerical/recovery/scientific cases → eventual evidence and model revision through C6/C3. MECE is used over workflow stages (model admission, compilation, numerical execution, comparison, persistence, consumer eligibility); domains, feedbacks and rival mechanisms can overlap and are not falsely partitioned.
