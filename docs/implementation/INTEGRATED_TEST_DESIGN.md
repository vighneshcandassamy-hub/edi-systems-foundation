# Holistic integrated test design — proposed, not executed

21 October 2026. Version 0.1. Owner instruction: finalize integration and design tests before testing. **No case in this document has run.** This is a reviewable protocol and coverage plan, not a result, automatic approval to execute, or completed scientific preregistration. Original source catalogues and their historical statuses remain unchanged.

## 1. Questions and distinct claims

1. Engineering: can the current source move native observations through C1–C7 under durable C0 orchestration without losing evidence, boundaries, uncertainty or authority?
2. Modeling: can supported structures produce the intended range of behaviors under different initial conditions, drivers, delays, nonlinear regimes and actor information?
3. Intelligence: can a pinned reasoning system propose discriminating rival mechanisms, seek useful adjacent/deeper information, detect change, and revise persistently without hindsight leakage?
4. Advantage: does EDI improve prospective prediction, unfamiliar-system transfer or useful decisions relative to strong matched alternatives, with acceptable total experiments, latency, tokens, compute and energy?

Passing question 1 does not answer questions 2–4. Correctly refusing an unsupported mechanism verifies a boundary; it does not demonstrate that mechanism's modeling capability. An authored model, imported rationale or test-operator decision is not autonomous discovery. Native vLLM/student/teacher execution is still unbound, so the first future engineering handoff and a later autonomous intelligence test must have different labels.

The [integrated workflow](C0_INTEGRATED_WORKFLOW.md), [Meadows architecture](../../architecture/world-model/Meadows_EDI_Integrated_Architecture_v0_8.md), [appendix semantics](../../architecture/reference/Meadows_Appendix_187_203_Semantic_Foundation_Reference_v1_0.md), [original verification authority](VERIFICATION.md) and [scaling/world-growth requirements](SCALING_AND_WORLD_GROWTH.md) govern the protocol.

## 3. Staged scenario portfolio

### P1 — controlled accumulator: smallest integrated engineering demonstration

Use an isolated local file as a real measurable accumulator. The stock is its byte count; a separately instrumented local writer supplies inflow. An authored coherent dimensionless-count stock/flow law predicts counts. C2 decoding and C3 candidate admission are explicit; initial rate is an assumption, not a discovered mechanism. No production files or external systems participate.

Freeze a nominal sampling schedule and plateau windows before sealing forecasts. Record each actual OS read time, scheduling jitter, file identity and byte count. The raw measured count must come from `stat`, never C5's output or the evaluation answer. An exact-match nominal-time correspondence is eligible only when the file is stable over the declared sampling window and jitter is inside its frozen tolerance. A missed/ambiguous sample remains missing/ineligible; do not backdate an observed value. Clock assumptions remain part of the result.

Proposed analytic fixture: initial count 8, candidate inflow 4 counts/s, nominal horizon 2 s, predicted endpoint 16. A planned changed-writer variant reaches 20, creating an expected signed prediction error −4 and absolute error 4. These are **design calculations**, not measurements or executed solver results. The control value and planted change are authored by the fixture designer; they cannot be called unknown causal discovery. Freeze numeric tolerance before execution; a proposed 1e−6 count numerical tolerance applies only to this constant-rate model, not ecological validity.

Required path: register native sources → record initial account → C2 decode/submit → C3 candidate hosting and separate operator modeling-use decision → C4 inquiry/rivals/test proposal and explicit model handoff → C5 compile/run → C6 post-commit future seal → later OS observations → fixed-cut C6 comparison → attributed C6 review/candidate revision/finding → C7 access review/proposal and separate operator decision → authorized internal inspection → C0 internal finding delivery.

Use a generated outcome control with identical scalar content but explicit generated lineage; it must remain unscored. Also include a null/no-change condition, denied external action, a missing sample and a stale-policy dispatch. Do not require a cause to be “identified” from one residual. The expected conclusion can be “rate change, unmodeled write and measurement problem remain distinguishable rivals; inspect additional evidence.”

P1 may use clearly labeled authored/manual responses to verify the C4 handoff. Such a run establishes orchestration only. For any native LLM claim, use a separately frozen model/checkpoint/tokenizer/gateway profile and real inference usage; an imported fixture cannot substitute for it.

### P2 — coupled nonlinear ecological system

Use a separately implemented, versioned test world inspired by the budworm example, not a transcription of the story's answer. Include tree age/food stocks, insect reproduction, saturating predator response, climate triggers, forest recovery and a management actor. Expose fragmented observations, not hidden state or generator equations, to every contender. Retain the simulator's complete oracle privately for evaluation.

Vary initial composition, weather, predator capacity, maturation/recovery times and intervention schedules. Demand predictions across quiet, growth, outbreak, food depletion and recovery regimes, including counterfactual interventions and delayed consequences. Add observation noise/missingness and plausible alternative structures that fit early data. Some cases must be nonidentifiable from the available channels and require abstention or discriminating acquisition.

Extend to logging, mill demand, wood prices and trade only in the world-growth stage. Local ecological stability and economic stability must use separate stakeholder criteria and horizons. Spraying is an intervention with multiple pathways, not a scalar “pest reduction” edge. Real feedback dominance and saturation must follow explicit equations/history and resource constraints.

Current C5 flat stock-state IR cannot silently stand in for unsupported delay/cohort/hybrid/actor dynamics. Build and qualify the needed adapter first, or mark those portions blocked. A rejection is an integrity result, not a full P2 pass. A simulation-inspired result is not an empirical discovery about a real forest.

### P3 — households, information and latent human causes

Compare rival worlds: visible meters causally change attention/use; energy-conscious households select meter placement; building layout changes both placement and demand; occupancy/weather/pricing causes the association; or several pathways interact. Supply event reports, temporal usage, placement history and channel availability separately. Let some variables remain unobserved, including cognitive/physiological causes.

First present only observational differences. EDI should preserve uncertainty and avoid treating a one-third association as a proven intervention effect. Later offer discriminating evidence, randomized assignments in a synthetic world, controlled changes or additional measurements where feasible. Test whether beliefs and conditional predictions change appropriately. “Human behavior is complicated” is not an explanation; an invented hormone mechanism without evidence must stay a hypothesis.

Represent actor-specific received information, memory, frames, goals, policy, delay and feasible response. Keep analyst-only variables outside actor views. Compare actual-world/model changes and intention/completion/effect separately. True human causal claims would require an independently designed empirical study; this protocol does not authorize one.

### P4 — cumulative world expansion and transfer

Begin in a small local system, then expose adjacent dependencies, internal mechanisms, older/newer reports and shared global drivers. Include both useful and irrelevant possible expansions. Example: insect → feeding physiology → tree composition → logging → furniture demand → trade/finance; boundaries/horizons/values must expand explicitly rather than silently changing the original forecast question.

Test the seven frontier directions: adjacent expansion, internal refinement, identity resolution, temporal refresh, mechanism testing, boundary review and abstraction review. Include same referent across modalities, look-alike different sources, source replacement/reset, late correction, revoked/expired access, denied requests and repeated requests. More questions or a larger graph is not success. Measure useful discriminations, avoided experiments, retained uncertainty and future-task benefit against acquisition cost and distraction.

Separate repeated familiar tasks, nearby structural variants and unfamiliar mechanisms. Include misleading prior history and source-dependence controls. Measure negative transfer as well as benefit. Keep held-out tasks inaccessible during development and prevent test-world oracle information entering model context, manual annotations, retrieval, teacher critique or operating policy.

### P5 — operational failure and long-run capacity

Inject duplicates, conflicting IDs, reorder, missing inputs, parser/schema incompatibility, stale revisions, generated echoes, unknown clocks, hash mismatch, partial replay, denied tools, full quotas, slow/unavailable reasoning, interrupted native invocation and lost receipts at each owner boundary. Distinguish no mutation, committed outcome, uncertain outcome and reported completion.

Exercise C0 restart and attempt fencing, C1 continued intake during downstream unavailability within capacity, C2/C3 staged proposals, C5 run/cancel/interrupt status, C6 original seals/cuts and C7 reconciliation. A live worker must be stopped/established inactive before a recovery retry that could overlap it. Record every offered failure; do not remove unavailable requests from denominators.

Use increasing source/history/graph degree and burst levels under pinned hardware/OS/configuration. Include hot shared referents and invalidation cascades. No finite test proves arbitrary scale. Local single-host SQLite cannot establish distributed HA merely by surviving a restart. Backup/restore/migration/HA cases remain blocked until implemented and specified.

## 4. Comparison arms and information parity

Before any intelligence/advantage comparison freeze at least: (A) the same pretrained LLM with ordinary task history, (B) the same LLM with strong retrieval/episodic memory, (C) the same LLM with a structured relationship/action-response memory, and (D) LLM+EDI. A long-context variant and a domain-specific oracle are useful diagnostic references where feasible. The oracle is an upper-bound diagnostic, not a deployable competitor.

Match model/checkpoint, evidence cuts, tools/action rights, permitted experiments, problem statements, human hints, teacher access and total budgets. Log both fixed-budget and equal-quality operating points when justified. If EDI uses simulation or structured records, make equivalent tools available to the baselines or explicitly state that the claim compares whole tool stacks, not memory alone. A disabled or deliberately weak conventional memory baseline cannot establish advantage.

Add ablations for persistent relationships, uncertainty/rival tracking, active exploration, temporal invalidation, teacher critique and cross-task memory. Freeze a manageable subset before running; do not create an unbounded combinatorial sweep. Manual assistance must be matched across arms or exclude that run from autonomous comparison.

## 5. Measures, standards and decision rules

| Claim | Primary evidence | Necessary controls / limits |
| --- | --- | --- |
| Integration | Correct native handoffs, retained source/forecast/model/policy IDs, expected refusals, durable restart and authority boundaries | No critical evidence/authority violation; planned cases remain unrun until pinned evidence exists. |
| Representation | Correct stocks/flows/roles/units/temporal cuts and support for several behaviors under varied conditions | No metric that merely rewards copying the fixture schema; unknown structures remain explicit. |
| Prediction | Prospective scalar errors and suitable probabilistic proper scores, coverage/missingness and calibration | Seal original standards before outcome; stratify domains/units/dependence; no fabricated confidence from tiny correlated samples. |
| Mechanism discovery | Discriminating predictions/interventions, supported structure changes and appropriate nonidentifiability | Fit alone does not identify a mechanism; keep planted cause separate from observable identifiability. |
| Inquiry | Useful discrimination/decision benefit per acquired observation or costly experiment | Include failed/inconclusive/unavailable acquisition and denial/cooldown; question count is not intelligence. |
| Transfer/growth | Held-out task improvement, surprise detection, negative transfer and useful refinement | Genuine history versus matched placebo/unrelated history; prevent oracle/hindsight leakage. |
| Decisions | Criterion-specific outcomes across parties/horizons, constraint compliance and unintended delayed effects | Intended action, adoption, execution and effects separated; no “optimal” label from a single selected value function. |
| Efficiency | End-to-end latency, active service/queue time, total inference/retrieval/tool/retry tokens, CPU/GPU, peak RAM/storage and acquisition count | Include pauses and human time separately; unknown costs stay unknown. Measure energy if available rather than infer it from tokens. |
| Availability | Eligible offered/accepted/completed/failed/unavailable requests, freshness and recovery loss/time | State fault model and capacity; distinguish process restart, data durability and HA. |

C6 currently supports finite scalar/Bernoulli scoring and descriptive calibration only. Additional distributions, censored likelihoods, causal/decision metrics and uncertainty intervals require separately specified implementations. Do not call those metrics available merely because this plan names them.

For P1, freeze exact expected identities/values/error/refusals and tolerances in an immutable manifest. For P2–P4 comparative claims, select primary endpoints, minimally useful effect sizes, trial counts/power, uncertainty method, paired randomization, dependence handling and multiplicity policy **before execution**. These numerical scientific choices are currently unresolved because model/hardware/world noise and budget are unbound. Use a separate development pilot only after it is authorized; its results cannot become held-out evaluation data.

Declare success/failure/blocked/inconclusive at the claim level. Integrity failure blocks promotion even if average accuracy looks good. If EDI offers no advantage, retain that result and investigate the bottleneck; do not change acceptance or rerun until superiority appears. Fixed unchanged and insufficient-evidence cases must be allowed to remain unchanged.

## 6. Evidence and traceability package

Each eventual run requires: immutable protocol/fixture hash, source commit and eight owner profiles, exact model/tokenizer/provider/serving configuration, runtime/hardware versions, source registry/epochs and input hashes, access/selection history, every hypothesis/model/policy revision, original seals, outcome cuts and missingness, operator/assistance provenance, commands/receipts and separate effects, failures/retries/cancellations, measured usage plus unknowns, and a machine-readable report with supporting artifacts.

Use run-scoped disposable databases and reproducible fixture seeds. Preserve first failures and repaired reruns separately. State whether the review is independent. Keep secrets, credentials, session data, raw private records and large runtime databases out of Git. The source/protocol and sanitized evidence may be saved in the authorized private repository; no sharing or deployment is implied.

Original cases in TRACEABILITY.json and component traces remain authoritative within their scopes. New C0-W requirements map to IT01–IT24 in [INTEGRATION_TRACE.json](INTEGRATION_TRACE.json); the broader P2–P5 portfolio allocates future work rather than duplicating or silently passing the original 192 architecture scenarios.

- Concrete P1 native workflow/fixture manifest and jitter/clock policy frozen; real measured values independent of forecast output.
- Exact student/teacher model/checkpoints/tokenizers/gateway/hardware if claiming native reasoning; export/import-only runs explicitly labeled otherwise.
- Supported C5 dynamics for each scenario; missing delay/actor/refinement adapters listed as blockers.
- Authenticated deployment boundaries before exposing trusted operator APIs to untrusted callers.
- Frozen baseline implementations, common budgets/information cuts, sample/statistical protocol and primary acceptance thresholds before comparison.

This design is deliberately wider than the first execution. Start later with the frozen P1 engineering path; use its results to repair integration, then qualify the missing mechanisms needed by P2–P5.
