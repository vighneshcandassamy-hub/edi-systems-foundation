The first completed automated pair, Kaggle version 363058667, terminated without a final participant report or elapsed simulation year in either arm. Baseline made two model calls, invented stand IDs and yielded after a rejected action. Native EDI made 64 model calls and repeated the same failed internal-record-ID asset lookup. A shared transport-side binding constrains public IDs to those already returned to that arm by successful public operations. It adds explicit recent public receipts, rejected intents, finite decision accounting and final-report instructions to both arms. Its immediate operation list is restricted to one proposal per response, matching the baseline's single immediate action. Native admission, C0/C7 authority and broker validation remain mandatory. Teacher-review is excluded because the teacher is disabled. No generated action is silently rewritten into a successful action.

The read-only public view queries only events(operation,response) and attempts(operation,status) in its own broker database. It never queries state, identity, private evaluation or the other arm. Document IDs come from search/read/ask responses; people/source IDs retain separate namespaces; stand IDs come from typed public JSON/CSV fields. An internal EDI evidence record UUID cannot become a public document merely by appearing in context. Missing IDs leave discovery operations available. Invalid read IDs are removed after a definite 404. An operation rejected at a fixed public cut is excluded until a new successful public response changes that cut. These constraints supplement existing broker authority; they do not guarantee valid budgets, scientific inference or ecological success.
