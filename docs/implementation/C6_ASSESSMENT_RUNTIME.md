## Registration contracts and prospective semantics

`SealRequest` identifies workspace/request/forecast/run/variant, case IDs, exact stock/relative-time samples, expected C1 origin/variable, declared dependence group, interpretation/score limit, interpretation basis, evaluation rule, assumptions and rationale. The selected run must be a completed numerical C5 run with a supported compiled artifact and matching content hashes. It needs a known absolute scenario time origin and native output correspondence. Each case uses an existing exact sample and native unit/ref; no nearest-time lookup or post-outcome interpolation. Cases are unique by ID and by origin/variable/target time within one forecast denominator.

The durable `ForecastSeal` retains the full C5 run request and IR snapshot, selected active parameters, model/compiled/run IDs and hashes, model refs/assumptions, original inputs and source IDs, outcome origin/epoch bindings, extracted predictions, scoring rule, C1 watermark and operating profile. This preserves operational policy/driver/solver context actually represented by C5; it does not invent a C7 policy version or certify modeled actor semantics. Source statement/correction status remains in the IR. Input C1 provenance/availability is checked; imported pretrained knowledge and unrecorded external knowledge remain an open limitation.

Registration requires future targets with a configured minimum lead. First the forecast payload commits; only after that call returns does C6 observe the host UTC acknowledgement time and persist a separate immutable confirmation referencing the seal hash. The forecast reserves confirmation quota up front. If a process dies between payload commit and confirmation, retry confirms at the **new current time**. If the target is no longer sufficiently future, confirmation is permanently `late-confirmation`; C6 never backdates it. A slow confirmation-record commit does not change the fact that the earlier forecast payload had already been acknowledged at the recorded time. These semantics assume a trustworthy common host clock; there is no external timestamp authority or proof of global knowledge independence.

The C5 run's original `forecast_seal=unsealed` field is retained as historical output. The C6 receipt is a separate owner-authoritative registration artifact; it does not rewrite C5. Corrections require a new run/forecast/request/confirmation identity and time; original forecasts and assessments remain available and scorable.

## Measurement format, held-out cut and deterministic selection

The supported observation adapter is **one raw external JSON measurement per C1 occurrence**: `capture.kind=measurement-v1`, `media_type=application/json`, known UTC event/report time and no unknown critical profiles. The payload uses `edi.measurement/1.0`: variable, aware `observed_at`, exact unit symbol, status and value or explicit missing/censoring bounds/reason. UTF-8, finite numeric values, duplicate-key rejection, strict fields and size limits are enforced. Original bytes remain C1-owned; C6 does not ingest or edit them. The example schema is not a claim that all real sources already conform.

`CompareRequest` pins an explicit `outcome_watermark` between the forecast cut and currently available C1 history. A retry therefore cannot acquire a newer outcome cut silently. C6 scans each sealed origin from position zero to that watermark in commit order. Scanning from zero matters: a matching occurrence already present before registration makes that case ineligible even if a later duplicate arrives. The first matching event-time/variable occurrence wins, including bad-unit, generated, missing or censored records; later corrections do not replace it under this rule. A new deliberately specified correction-aware evaluation policy would need a separate version and prospective registration.

An earlier unclassifiable measurement—unknown clock, malformed JSON or unsupported critical/media semantics—can block a later seemingly valid match. Its C1 reference and reason remain attached to the invalid assessment rather than cherry-picking past it. No matching record in an exhausted bounded origin prefix means missing **in that selection**. Budget/deadline/unavailability leaves `scan-incomplete`, never proof that no outcome exists. The model/source ecosystem outside the chosen origins remains unvisited.

Scoring requires a `local-prospective` confirmation, a new occurrence position after the registration watermark, receipt/commit strictly after confirmation, a future target relative to confirmation, exact payload/native event-time match and coherent event ≤ reported ≤ receipt ≤ commit order. Raw external origin with **empty generated/derived lineage** is required in this strict first profile. Generated/simulated/unknown or lineage-bearing outcomes remain ineligible even if reimported through an external-looking channel. C6 cannot detect a dishonest raw-source declaration or concealed provenance; signatures, external release-time attestations, source trust and hidden knowledge remain open.

Default policy rejects overlap between outcome source ID and declared forecast input sources. The rule can explicitly allow that overlap for a sequential same-instrument task before outcomes arrive; dependence is then flagged and never treated as independent corroboration. Origin epochs are distinct from persistent source identity. Declared dependence groups and unique source counts are reported separately; neither is a certified effective independent sample size. Different physical sources may still share unrecorded upstream causes.

## Scores, missingness and uncertainty

Point predictions report signed error **prediction − observation**, absolute error and squared error. Boolean data cannot silently become cardinal observations. The predeclared point score limit uses absolute error in the native unit. Unit symbols must match exactly; C6 performs no unit/aggregation conversion or normalization after seeing outcomes. Aggregate errors are stratified by quantity unit and interpretation rather than averaging kilograms and probabilities together.

An explicitly declared dimensionless C5 value in [0,1] may be interpreted as a Bernoulli probability with a recorded semantic basis. Only binary outcomes are then eligible. The binary Brier **loss** is `(p − y)^2`, lower being better; the prespecified limit lies in [0,1]. The quadratic scoring-rule foundation is [Gneiting and Raftery, 2007](https://sites.stat.washington.edu/raftery/Research/PDF/Gneiting2007jasa.pdf), checked 20 October 2026. This binary loss convention is not a new scoring method. Proper scoring does not make an LLM confidence label a calibrated posterior or turn a finite scenario envelope into a predictive distribution.

Missing and left/right/interval-censored data retain status, reason and bounds. They receive no ordinary scalar/Brier score or fabricated zero. All planned cases remain in the coverage denominator. Unscorable/ineligible/invalid/scanned-incomplete cases remain visible; limits are `incomplete` unless all planned cases are scored. `within-declared-limits` is only the result under that sealed rule, not a component/scientific gate PASS. Nonfinite arithmetic is rejected; aggregate overflow retains individual finite rows with a diagnostic instead of inventing a finite mean.

Calibration bins are fixed in the sealed rule, cover [0,1] and report counts, average probability, observed fraction and unique sources for eligible binary cases. These are descriptive summaries, not confidence intervals, significance tests or evidence of calibration under arbitrary dependence/selection. Continuous-distribution scores, censored likelihoods, causal identification, matched skill/transfer comparisons and learned calibration remain future methods. No source or parameter is automatically reset or trained after an error.

## Error diagnosis, revision and findings

Every comparison preserves the original forecast/confirmation, fixed outcome cut, selected raw measurement/evidence refs, source-coverage records, scores, denominators, limitations, usage and all eight candidate categories: observation error, semantic misalignment, numerical error, unexpected drivers, wrong parameters, wrong rule/topology, changed policy and non-identifiability. These categories begin **not established**; measured discrepancies do not automatically identify one.

`ReviewRequest` supplies attributed candidate/unknown cause hypotheses with support/counterevidence, discriminating test and uncertainty; explicit C3 target versions/revision; retain/revise/reject/investigate recommendation; retained rivals; expected benefit; new verification burden; rationale and optional candidate puts. Evidence must come from the immutable assessment cut. Even an ineligible source record may support an investigation about why capture/measurement failed; it does not become independent corroboration. Target snapshots and bounded dependent views preserve affected descendants and truncation. Inactive targets cannot be implicitly resurrected. The review is fallible advice, not automatic causal diagnosis, empirical acceptance or policy adoption.

Optional world edits use distinct hypothesis-only `Put` operations, selected base versions and pinned existing or explicit post-patch references. No admission/retirement operation is exposed. `build_patch` attaches bounded attribution summaries and exact C6 hashes/IDs; full advice remains in the immutable review. `submit_revision` stages the exact C3 patch, then proposes through the C6 candidate port, then stores the C3 receipt. Receipt space is reserved when staging. A lost C6 receipt is reconciled by retrying the original staged C3 request; there is no hidden rebase or distributed transaction. C3's admission authority remains unchanged.

`FindingRequest` records newness/priority basis, affected parties/goal/horizon, hypothesized/associative chain, support/counterevidence, alternatives, uncertainty, suggested observe/investigate/simulate/review-policy class, expiry/review trigger and attribution. Output is an immutable **draft**; it does not send a notification or execute/adopt an action. C0 retains delivery/deduplication; C7 retains authorization/adoption. Counting finding drafts is not strategic usefulness.

`YieldRequest` links explicit comparison snapshots to an inquiry, declared exposure, resource account, selection basis and caveats. Duplicate assessment IDs or repeated forecast cases across snapshots are rejected rather than inflated. Result reports linked coverage/source counts and hashes. Selection/exposure and resource measurements remain caller-declared; matched information gain, usefulness, calibrated advantage and complete efficiency are **not established**. This is the first native C4–C6 review interface, not proof of intrinsic curiosity or better learning.

## Operating envelope, failure analysis and retrospective

Defaults: 256 KiB request, 4 MiB artifact, 8 MiB context/page, 128 forecast cases, eight outcome origins, 256 declared input refs, 2,000 scanned records, 100-record source pages, 16 KiB measurement payload, 1 MiB total read bytes and cooperative 15-second operation budget. Up to 16 revision targets/candidates and 32 linked assessment snapshots. The local store reserves up to 50,000 logical artifact rows and 1 GiB encoded content plus prepaid confirmations/receipts, with a 256 MiB disk reserve and five-second writer timeout. A single in-process operation slot bounds local concurrency; immutable request/ID constraints serialize competing commits. These are finite local profiles, not measured HA, arbitrarily scalable storage or instantaneous intelligence.

Work metrics retain source records/bytes read and elapsed comparison time; no mandatory LLM calls/tokens. They do not measure complete C0–C6 path latency, energy, CPU, all failed pre-admission work or scientific utility. Timeouts are cooperative; host/storage calls and JSON parser work are not forcibly isolated. Physical SQLite/WAL overhead is not the encoded-content quota. Fair durable workers, source/time indexing, process supervision, retention/export/restore, migrations, replication/failover and complete cost remain open.

| Failure / condition | Containment and preserved evidence |
| --- | --- |
| Crash after forecast payload, before confirmation | Payload persists; retry uses current acknowledgement time; late confirmation cannot become prospective. |
| Already available, repeated, generated or source-overlapping outcome | First occurrence and original lineage retained; sealed eligibility policy applies; no later favorable substitution. |
| Unknown clock/unit/aggregation, malformed record, missing/censored data | Explicit invalid/ineligible/missing/censored row; no synthetic scalar score or denominator removal. |
| Scan/read/time quota or retrieval outage | Prefix/cut/stop reason retained; unexamined cases are incomplete, never universal absence. |
| Request conflict, full store or unknown commit | Original request/status/artifact identity reconciles; confirmation/C3 receipt already reserved; physical disk repair may still be required. |
| Wrong model/parameter/drivers versus noisy observations | Preserve eight rival error categories and discriminating-test advice; no single automatic blame or acceptance reset. |
| Lost C3 submission receipt / changing world | Exact staged candidate patch can be retried; no silent rebase or direct adoption. |

KISS: one immutable artifact ledger, one narrow measurement adapter and small explicit scoring/selection functions. Reuse C1/C3/C5 ports; do not import an agent/calibration/experiment platform or duplicate raw records/world state. Five Whys: honest learning needs an original expectation; originals need fixed correspondence and criteria; held-out comparison needs durable prior registration and actual outcome availability; that requires separate confirmation/time/cut/lineage checks; therefore C6 separates immutable forecast payloads, confirmations, comparisons and fallible advice.

Waterfall/return path maps mission → IMP requirements → F60–F63 → contracts/functions → bounded code → specified future cases → eventual evidence/C3 review. MECE is an audit aid over registration, correspondence/selection, scoring, diagnosis, revision/delivery and resource/recovery obligations; real causes and system interfaces can overlap. Scalar loss, calibration, causal explanation and policy usefulness are different assessments and are not collapsed into a universal truth score.
