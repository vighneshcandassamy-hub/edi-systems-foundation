# ADR-007: Restricted stock/flow IR and optional pinned SciPy scenarios

Status: adopted for the first source increment, code 0.6.0; contract/runtime/integration qualification remains open.

C5 must execute conditional mechanisms without letting a reasoning model run arbitrary code or turn trial state into observations. C4's source inquiry/proposal subset is available, but native inference and full C4 acceptance remain open. C0 can route an explicit C3-backed analysis without introducing a C4–C5 bypass.

Use a flat typed expression DAG embedded in a versioned native joint response, with typed stocks, flows, parameters, drivers, coherent units, domains and source-formalization rationale. Compile against exact C3 versions, native stock/flow inventories and complete/current bounded dependency views. Reject unsupported laws and any unrepresented native delay, capacity, pending commitment, reserve/access or transformation semantics.

Use the existing selected SciPy direction rather than build an unqualified proprietary solver. The optional numerical extra pins local metadata SciPy 1.17.0 and NumPy 2.5.3; loading is lazy and no installation occurred. The compiler, model/native correspondence, units, budget accounting, hypothesis/scenario lineage and run-state lifecycle are EDI-owned code. A versioned `solve_ivp` adapter handles declared ODE methods/tolerances and segmented boundary drivers. Official API: https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.integrate.solve_ivp.html (checked 20 October 2026). Solver support does not establish model truth, numerical adequacy, complete event detection or general DAE/delay/hybrid support.

Alternative stateless scripts lose immutable context/retry identity and permit arbitrary execution. A general symbolic language or immediate PySD/SimPy/Mesa stack adds semantics/dependencies before requirements justify them. A custom ODE implementation adds a numerical validation burden without demonstrated benefit. Future backend adapters remain possible under the same C5 owner, explicit capability grammar and qualification obligations.

Persist compiled artifacts, run intents and final conditional outputs in C5's separate lazy SQLite store. Reserve bounded result/control capacity before work; maintain one active worker per workspace; preserve unknown completion and require explicit cancellation/fencing instead of automatically repeating a crashed run. Trial outputs remain simulation-origin, unsealed for independent C6 comparison, and immutable even after parameters/models evolve. Finite variants/ranges/secants do not represent a calibrated posterior or identified causal derivative.

Consequences: this is a narrow useful stock/flow subset with explicit unsupported outcomes, not all of systems dynamics. It does not implement actor policy, arbitrary delay history, resource arbitration, topology transitions, full uncertainty inference, C6 registration, process supervision, retention/restore or HA. [C5 specification](../implementation/C5_ANALYSIS_RUNTIME.md), [trace](../implementation/C5_RUNTIME_TRACE.json) and source review retain these obligations and the user's structure-first deferral of all runtime/product qualification.
