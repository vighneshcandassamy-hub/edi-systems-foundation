# ADR-004: C3 versioned world hosting and explicit modeling-use admission

20 October 2026. Code version 0.3.0. Input architecture/code revision `bd8b05d6c17114fe6747c18801399444838125a3`. Status: first local source implementation, unqualified. Owner explicitly authorized C3 after the foundation/C1 increment; qualification/tests remain deferred under the existing sequence.

C3 is one owner with representation contracts, admission/revision coordination and a bounded SQLite store. The retained substrate's SUB-C1/SUB-C2/SUB-C3 are historical internal labels, not the current global C1/C2/C3. Under the eight-owner architecture, C3 now hosts/admits; C4 handles inquiry, C5 executes dynamics, C6 assesses and C7 owns actual operational adoption. No old three-part inquiry coordinator is silently added to C3.

Reuse nine representation families with discriminated typed structures, attributed evidence, explicit uncertainty and valid-time scope. Use typed references with participant roles and direction; preserve overlapping/nested compositions and multi-party relationships without forcing every phenomenon into a numeric stock or binary edge. Generic properties are opaque: no hidden reference, unit, conservation or executable-code semantics are inferred.

One cumulative world is stored per workspace; scope/view labels do not create separate memories. New adjacent systems and finer structures can reference existing identities. Committed references pin exact target versions; corrections append versions, leaving previous snapshots and rivals inspectable. No physical identity merge is inferred from representation IDs.

Use a separate C3-owned SQLite database so C1 receives no model-write dependency. C3 reads C1 metadata through IF-09's limited evidence facade; it never opens or mutates C1 tables. Commit model changes, dependencies, retry result and selected consumer progress together in C3. A later C0 call can advance the C1 checkpoint. No distributed transaction, evidence-retention lease or exactly-once external action is implied.

Candidate proposals from allocated component ports cannot promote themselves. A trusted local operator can append a scoped accepted-for-use/rejected/withdrawn decision under local-modeling-use/1.0, recording rationale, use scope and remaining verification. Accepted-for-use needs linked source evidence or explicit assumptions. It never establishes empirical truth, independent corroboration, numerical validity or causal identification. A changed put resets admission to candidate unless the local operator explicitly supplies another decision.

Append-only versions, optimistic base/record version checks and one revision-pinned SQL read path are simpler than a graph/vector stack plus cache synchronization. A current-head projection and reverse dependency index are committed with history. Every commit invalidates `world.current` at the revision boundary. Bounded dependency queries report stale/inactive targets and truncation; no list is falsely described as exhaustive transitive invalidation. Specialized caches and selective incremental revalidation are deferred.

Alternatives: mutable JSON would lose revision/admission semantics; full-model copies on every change grow unnecessarily; a service per Meadows term adds no needed authority; starting Postgres/graph infrastructure would add installation/operations before a real consumer. PostgreSQL remains a later adapter behind WorldStore, requiring migration/compatibility qualification. The local adapter establishes no HA or measured scalability claim.

No new dependency is installed; Python/Pydantic/SQLite bindings follow ADR-003. New source uses the same documented sqlite3 transaction/progress-handler APIs and Pydantic model API. Detailed scope, eleven interface facets, source-review findings, unrun cases and examples are in [C3 runtime specification](../implementation/C3_WORLD_RUNTIME.md). Original conceptual snapshots and previous evidence are unchanged.
